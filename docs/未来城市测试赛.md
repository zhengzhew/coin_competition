# 未来城市 · 循环挑战

## 当前版本：9/16 六关课程 3.0

`/future/` 已切换为 玩法整理落地的六关：方形巡航、进退有序、城市巡逻、环线配送、鱼骨巡检、鱼骨配送。新编号 FL31—FL36，版本 `future-loop-3.0.0`（底板与镜头按实际内容收边，保留全部可走格）。来源、逐关目标、地图转换边界及验证说明见 [9/16 关卡设计](916关卡设计.md)。

代码模式默认选中空白循环框，由学生填写循环次数和循环体；全部指令放在循环体内。仅第 2 关的打卡点显示字母并要求指定顺序，其余打卡点使用统一图标。地图右上角显示随镜头转动的指南针，小车旁不再显示 W/S 提示。重新开始与重新挑战保留本关代码；切换关卡时使用新的空白循环框。

当前六关采用 60/80/100 分档：完成全部目标得 60 分，行动次数达标得 80 分，代码模式再满足行数标准得 100 分；未完成得 0 分，键盘最高 80 分。行动标准依次为 19、27、26、25、35、28 次，代码标准为 3、4、5、7、7、8 行，均按不超过标准判定。历史成绩不自动重算。

## 历史版本：循环搬运 2.0

`/future/` 现在展示 6 个循环搬运场景。道路由独立可行走格、货物泊位和逐渐抬升的桥面组成；宽度随场景变化，最大 20 格宽。城市背景不受棋盘形状限制。

| 按键 | 动作 | 代码 |
| --- | --- | --- |
| W / ↑ | 沿车头前进一格 | `forward(n)` |
| S / ↓ | 沿车头后退一格 | `backward(n)` |
| A / ← | 原地左转 90° | `turn_left()` |
| D / → | 原地右转 90° | `turn_right()` |
| G | 夹取车头前一格货物 | `grab()` |
| R | 松开到车头前一格 | `release()` |

每次仅能携带一箱。前方是空隙、障碍或已有货物时不能放下；放错位置可以重新夹取。送达同字母泊位才计为完成，经过货物不会自动收集。界面主要显示“行动次数”：前进一格、后退一格、转向一次、夹取一次、松开一次均计 1 次；未成功的操作也计入，镜头操作不计入。循环按展开后实际执行的动作累计，完成后未执行的部分不计入。移动步数与碰撞仍供底层诊断，不作为未来城市界面重点。完成数量占 60 分，全部送达奖励 40 分；循环与键盘使用相同规则，不额外按是否使用循环加减分。

代码区可添加循环块、设置 1—20 次、选中循环后插入六类指令，也可添加循环外指令。前进/后退次数为 1—20，程序展开最多 256 条；后端保存展开动作和程序快照并按同一规则核验。

代码模式显示当前行数和最优目标：每条指令 1 行、循环头 1 行，循环体按写出的行数计算，不按次数展开。第 1 关目标 4 行，第 2—6 关目标 8 行，由 `optimal_code_lines` 配置；参考程序均通过规则回放验证，目标作为教学参考而非通用程序最短性求解证明。仅完成配送后显示精简反馈，并固定使用本轮运行时的行数；运行后修改编辑器不会改写本轮结果。该指标与行动次数分开，不改变现有配送计分。埋点记录 `code_line_count` 和 `optimal_code_lines`。

新任务编号为 FL21—FL26 / FK21—FK26 / FP21—FP26，内容版本 `future-loop-2.0.0`。旧 FL01—FL20 保留查询和回放，历史成绩与次数不混入新关卡。金币赛保持原玩法。

## 玩法与场景

未来城市以飞空车收集能源、规划航线为任务。地图中的金币对应普通能源芯（1 点），金币箱对应超级能源芯（3 点），障碍对应城市高楼。

以下行为复用原实现：20 张地图的坐标、大小、障碍、目标位置与价值；关卡分组和顺序；进入时选择键盘或代码模式；方向键、WASD、方向按钮；点击加入 `move_*()` 指令、填写 1—20 步、逐行删除；顺序收集、路线评分、步数预算；每任务 3 次正式尝试、最高分及后续练习。

代码模式仍然运行学生编排的确定性移动指令。场景中的“自动执行”指程序执行航线。

## 项目结构

新测试赛有独立 HTML 入口，通过 Vite 多页面构建输出 `client/dist/future/index.html`。两个入口复用同一 React 页面、操控组件、规则引擎和 API，避免后续两套规则发生偏差。

| 文件 | 内容 |
| --- | --- |
| `client/future/index.html` | 新测试赛入口、标题和页面信息 |
| `client/src/theme.ts` | 按入口选择场景名称和图标 |
| `client/src/FutureCity.css` | 未来城市专用样式，不覆盖金币赛 |
| `client/src/components/CityBoard3D.tsx` | 3D 地图入口、视角按钮、全屏与轻量回退 |
| `client/src/components/ThreeCityScene.ts` | Three.js 场景、飞空车模型、平滑移动、轨道相机和资源释放 |
| `client/src/components/CityBoard.tsx` | 3D 不可用时的轻量地图：斜俯视平台、立体高楼和坐标投影 |
| `client/src/components/CityBoard.css` | 立体地图的线条、阴影与悬浮动画 |
| `client/public/assets/future/` | 本地 SVG 城市背景、飞空车、能源芯和高楼 |
| `shared/src/competitions.ts` | 从原地图派生未来城市任务编号与文案 |
| `server/src/levels.ts` | 两套任务的读取与服务端规则匹配 |

画面延续原有横向 16:9 结构：左侧选关、中间地图、右侧控制及结果。素材随项目部署，无外部图片、字体或 CDN 依赖。减少动态效果的系统设置会关闭主题动画。

中间地图默认采用 Three.js / WebGL 真 3D，支持拖动旋转、滚轮缩放、右键平移，以及 3D、俯视、跟随、复位和全屏。全屏显示地图及原控制区。相机不监听方向键，方向键与 WASD 继续操控飞空车；相机旋转不会改变地图坐标的含义。场景边缘的 x+、y+ 标记用于辨认方向。

跟随视角支持拖动旋转与滚轮缩放，飞空车移动时保留调整后的角度和距离；该视角关闭平移，使观察中心持续跟随车辆。

飞空车旁显示上、下、左、右四向指示，按地图坐标投影到当前镜头，随旋转和车辆移动更新。文字保持正向可读，指示不拦截拖动操作；键盘和代码指令仍使用相同的固定坐标。

飞空车使用本地几何模型，按规则引擎的路径逐格平滑移动并转向。网格坐标 (x,y) 映射为 3D 世界的 (x,高度,-y)，高度仅用于表现悬浮。能源拾取、顺序限制、碰撞和判分仍由原规则决定，渲染层不增加游戏规则。

3D 引擎作为独立代码块按需加载，不依赖运行时外部 CDN。切关会释放场景、纹理、材质、控制器和 WebGL 上下文。无法建立 3D 上下文或发生上下文丢失时，自动使用既有 SVG 轻量地图，操控和上报继续可用。

## 共用后台与数据区分

- **同一服务和数据库**：同一 `/api`、同一 SQLite，无新增学生数据副本。
- **同一身份**：同源两个入口使用原有 `player_uuid` Cookie；首次从未来城市进入的新玩家使用领航员等名称，已有玩家名字保留。
- **独立任务**：金币赛为 `L01—L20` / `K01—K20` / `P01—P20`；未来城市为 `FL01—FL20` / `FK01—FK20` / `FP01—FP20`。正式次数和最高分按原有“玩家 UUID＋任务编号”计算，两赛互不占用。
- **可识别来源**：新事件的 payload 带 `competition` 和 `content_version`；未来城市内容版本为 `future-city-1.0.0`。本地待上报事件按测试赛分开缓存。
- **教师筛选**：看板与导出均支持测试赛、完整关卡编号、UUID、模式组合筛选。成绩导出增加 `competition` 列；旧金币赛数据归为 `coin`。
- **删除范围**：既有的精确 UUID 删除仍删除该玩家在全部测试赛中的数据；界面明确显示完整范围，原确认步骤保留。
- **权威判分**：使用原重放接口，客户端不提交可采信的分数；最优步数与最高价值答案仍不向学生关卡接口公开。

接口示例：

```text
GET /api/levels?competition=future
GET /api/levels/FL01
GET /api/assignments/FK01
GET /api/teacher/dashboard?competition=future&level=FL01&mode=keyboard
GET /api/teacher/export?competition=future&kind=attempts&format=csv
```

部署时把整个构建产物与服务端一起更新。两个学生入口应放在同一域名；不要另启一个使用不同数据目录的后台来运行未来城市。原数据库无需迁移或重置。

## 验证

```bash
npm test
npm run build
npm run test:policy
npm run test:future
```

未来城市接口验证会创建并清理临时数据库，覆盖 20 张地图一致性、80 条对应参考路线判分、独立次数、身份共享、看板筛选和导出。

浏览器验证需本机可用的 Playwright 和 Edge。默认使用 `playwright` 包，可用 `PLAYWRIGHT_MODULE` 指定已有包路径；`BROWSER_CHANNEL` 可切换到已安装的 Chrome。

```bash
npm run test:future:browser
```

此脚本自行创建本机临时服务和数据库，不连接课堂数据。截图与验证结果保存在 `outputs/future-city/`，覆盖真实键盘和代码操作、顺序限制、预算结算、练习、金币赛回归、教师筛选，以及常用桌面尺寸的地图边界检查。
