# Vibe Coding 启动指令 V2.1

请依据本开发包实现新的线上“旷野淘金”校园初赛测试系统，工作目录新建 `coin-path-pilot/`。先读取：

1. `开发文档_V2.md`
2. `20关设计与Python输入.md` 与 `levels.teacher.json`
3. `全量埋点与玩家标识.md`、`玩家交互埋点清单.md`、`interaction_catalog.json`
4. `DEMO复用说明.md`、`demo_assets.manifest.json`、用户提供的 `DEMO/` 示例
5. `verification_report.json` 与 `solutions.teacher.json`

`archive_v1/` 是历史资料，不使用其中的7地图方案、800ms输入日志防抖、镜像两模式或40分钟完成全部任务的旧假设。当前必须交付 **20 张地图、K01–K20 键盘20关、P01–P20 Python20关**，两模式同编号共用同一地图。

当前内容包版本2.1.0，旧版2.0快照在`archive_v2_0/`；不要用旧的最多3枚金币或8×8限制。玩法规则与埋点schema仍为2.0.0，地图变更按content_version区分。

核心要求：

- 一开始自动创建并展示随机 UUID 与玩家称呼，跨刷新/关卡/模式保持；换一位学生才换身份，旧数据保留。UUID只是标识，不充当授权凭证。
- 每一个任务内玩家交互都有原始操作、语义事件和时间信息。先实现统一tracking组件与element_id注册，再实现界面。包括输入全过程、取消/拒绝/无效操作、声音/提示/滚动、键盘按下松开长按等，不能仅记录成功移动或最终代码。网络批量上传但逐条记录不采样，保留未开轮的草稿/教学流。
- 使用DEMO里的小车、金币、沙地、木障贴图和布局/动画语言，优先复用`assets_demo/`中已提取的文件。保持原DEMO不变，不把整份base64 HTML复制为正式系统。
- 只做四向单格移动、等值金币、静态障碍和路径规划，最后金币到手立即完成，不返程。不要直接沿用DEMO的1秒停留拾取、预算取舍、箱子价值与Manhattan裁判。
- 金币数量必须单调不减且最多6枚：01–03关1枚、04–07关2枚、08–10关3枚、11–14关4枚、15–17关5枚、18–20关6枚。后半段升级分区、凹形围墙和多层通道，最大10×10；计划槽位、标签A–F、计分分母与完成掩码全部动态生成。
- 按01–06探索、07–12给定顺序教学、13–20自主优化递进。每模式各20关全部可用；40分钟现场抽测是场次配置，不得因此只实现抽测12关。
- Python每关有明确可输入区域与白名单。P01–P04只输入方向，P05–P20输入方向和重复次数；固定代码不能编辑。按JSON限制行/段数。代码与键盘进入同一内核，支持单步/运行/停止，服务器独立验证冻结模板的指令前缀。不执行任意源码，不提供自动寻路函数。
- Python与C++经历学生都可做两种模式；提供C++语法对照和公共练习，分别记录语言、模式与是否已见过同题。
- 实现服务端玩家/场次/轮次、持久数据库、所有事件流、IndexedDB恢复、幂等上传与完整性检查、精确BFS裁判、教师进度/导出/回放/补机会。只有命令和得分正确、但原始交互流缺段，不能标成全量收卷成功。

开发顺序：规则与40任务配置 → UUID与全量埋点基础 → 两模式完整页面/教学 → 服务端持久化/恢复/裁判 → 教师端 → 浏览器交互覆盖与并发、学校网络测试。

先运行本包 `python verify_assets.py` 确认固定参考数据；新应用需提供独立单测、E2E和负载脚本。以主文档P0验收为准，提供所有77种交互位置模式和动态实例的真实浏览器日志证据，而不是只把JSON清单抄进源码。所有40任务要有可以完成的键盘/代码记录；样例程序只是开发参考，不公开给学生。

维护实施状态：待实现、代码完成、单测通过、浏览器通过、已部署、学校实测。提供启动/构建/测试/备份/恢复命令及配置示例，完成后给真实部署链接。缺少部署目标或凭据时，先完成本地系统与可部署产物，明确外部阻碍，不虚构网站或完成状态。

这是开发系统的指令，不要求自动创建新任务或调用多个代理。正常可逆实现和测试直接推进；保护用户原有DEMO和历史资料。
