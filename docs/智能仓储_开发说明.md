# 智能仓储开发说明

智能仓储是独立的第五赛项，入口为 `/warehouse/`。六关均使用按键驾驶、物理夹取与释放，一箱一格；全部箱子有效送达后停表，不设时间上限，不设区域分值或分数目标，只以完成用时作为成绩。总入口 `/home/` 提供赛项入口，赛项内部的“返回首页”回到仓储关卡选择页。身份页、关卡导航、任务区、操作区、完成反馈和底部排行榜沿用其他赛项的共用模板。

## 操作与计时

| 操作 | 按键 | 行为 |
| --- | --- | --- |
| 前进、后退 | W、S 或上下方向键 | 按住行驶，松开制动 |
| 左转、右转 | A、D 或左右方向键 | 原地转向 |
| 闭合夹爪 | G | 接触箱子后通过夹爪摩擦夹持 |
| 张开夹爪 | R | 释放当前夹持的箱子 |

页面同时提供可长按的驾驶按钮。按“开始计时”后启动本轮；达成任务时立即停表并禁用驾驶。箱子必须释放并停稳 0.4 秒才确认送达，停稳时间计入完成用时。

切换视角、松开按键、窗口失焦均不停表。失焦或页面进入后台会清除驾驶输入，避免卡键。后台恢复后继续累计实际经过的时间，物理模拟限制单帧追赶量，避免大时间步造成穿透。

“结束本轮”停止当前挑战且不保存成绩；“重新开始”恢复初始场景和零计时，等待再次开始。切换关卡也结束当前未完成挑战。

## 场地与关卡

场地为 120 × 120 cm，左下角是坐标原点，X 向右、Y 向上。以下均为物体或区域的中心坐标。渲染与物理使用 `x=X、z=120−Y`。

小车中心为 `(12,12)`，初始朝右；第一个箱子中心为 `(24,12)`。第三至六关箱子沿 X 方向排列，中心间隔 12 cm。箱子边长 6 cm，区域边长 12 cm。

| 关卡 | 箱子中心 | 投递区中心 | 完成条件 |
| --- | --- | --- | --- |
| 1 定点投递 | `(24,12)` | A `(84,84)` | 1 箱有效送达 |
| 2 定点投递 | `(24,12)`、`(48,12)` | A `(48,84)`；B `(84,84)` | 2 箱分别进入 2 格 |
| 3 目标达成 | X 为 24、36、48，Y 均为 12 | A `(24,84)`；B `(60,84)`；C `(96,84)` | 3 箱分别进入 3 格 |
| 4 目标达成 | X 为 24、36、48、60，Y 均为 12 | A/B：X 为 24、96，Y 为 96；C/D：相同 X，Y 为 60 | 4 箱分别进入 4 格 |
| 5 目标达成 | X 为 24、36、48、60、72、84，Y 均为 12 | A/B/C：X 为 24、60、96，Y 为 96；D/E/F：相同 X，Y 为 60 | 6 箱分别进入 6 格 |
| 6 目标达成 | X 为 24、36、48、60、72、84、96、108，Y 均为 12 | A/B/C/D：X 为 24、48、72、96，Y 为 96；E/F/G/H：相同 X，Y 为 60 | 8 箱分别进入 8 格 |

区域以颜色和字母区分，外沿互不重叠。每个箱子可选择任一空投递区，无固定编号匹配；每关箱子数量与格子数量相等，完成时每格恰好一个有效箱子。后续关卡采用两排投递区，保留下方取货通道，可先安排远排再安排近排。关卡配置统一定义在 `shared/src/warehouse/levels.ts`。

仓储专用小车车身边长为 17.8 cm，夹爪总宽为 14 cm，以保证指定的小车、首箱初始坐标没有车身穿插。模型和物理尺寸同步应用这一配置；其他赛项仍采用原有默认尺寸。

## 有效摆放与完成判定

- **允许旋转、轻微压线，但箱子不得越过可见边线外沿。** 12 cm 是两侧边线中心线的距离；当前线宽为 0.6 cm，因此每侧最多允许占用中心线以外的 0.3 cm，外沿包围范围为 12.6 × 12.6 cm。
- 用旋转后的箱子四角判断是否完全处于外沿内，不以箱子中心进入区域作为送达依据。
- 箱子须经过实际夹持和 R 释放。直接推入但从未夹取释放的箱子不计为送达；仍在夹爪中的箱子不计为送达。
- 箱子线速度低于 0.5 cm/s、角速度低于 0.05 rad/s，且连续在同一区域停稳 0.4 秒，才确认为有效送达。
- 一个投递区只能容纳一个有效箱子。同格完整放入多个箱子时，该格所有箱子暂不计入送达，分开后重新停稳判定；尚未释放或仍被夹持的箱子也占据该格。地面刚体碰撞阻止箱子相互穿过，模拟没有升降和堆叠操作。
- 送达数量根据当前有效箱子重新计算。未完成时，重新夹取、移动出区域或失稳会撤销该箱子的送达状态；重复按 R 不会重复计数。
- 六关均在全部箱子各占一格、有效送达后完成。完成后冻结本轮状态和用时。

边线宽度和停稳时间集中在 `WAREHOUSE_RULES`。调整尺寸、线宽或关卡布局时，应重新运行边界和完整搬运验证。

## 代码与记录

| 文件 | 职责 |
| --- | --- |
| `shared/src/warehouse/levels.ts` | 六关配置、规则常量和版本 |
| `shared/src/warehouse/rules.ts` | 旋转边界、停稳、有效占用与目标判定 |
| `shared/src/warehouse/session.ts` | 实际时间、按键输入、固定物理步长和完成状态 |
| `client/src/warehouse/WarehouseApp.tsx` | 玩家、路由、关卡选择与成绩保存 |
| `client/src/warehouse/WarehouseWorkspace.tsx` | 驾驶、计时、进度、货物状态与完成反馈 |
| `client/src/warehouse/warehouse-arena.ts` | 场景、仓库装饰和投递区标识 |
| `client/src/warehouse/storage.ts` | 仓储独立身份与成绩读取 |
| `scripts/verify-warehouse-physics.mjs` | 六关完整物理搬运验证 |

复用 `SimulationScene`、赛考小车模型和 `ThirdPhysicsArena` 的地面刚体模拟。抓取由夹爪接触与摩擦形成，没有吸附、瞬移或自动驾驶操作。

仓储的两侧夹爪采用共同目标位置的电机同步控制，目标跟随较慢的一侧推进。此模式不使用将同一动态底盘同时作为两个基体的 `GearJoint`：Planck 1.4.2 在该组合下会分别回写底盘角速度，丢失部分反作用，造成松键后持续漂转。夹爪仍通过力和接触移动，未锁死车体朝向或直接设置箱子位置。

成功完成后使用共用的 `useLeaderboardSubmission` 提交到 `/api/leaderboard/submissions`，写入 `leaderboard_submissions`，教师端目录包含智能仓储六关。未完成不提交；每次运行使用独立提交 ID，失败可重试，同一提交不会重复入库。后端沿用其他手动赛项的完成记录提交方式，不进行输入轨迹重放。

排行榜复用 `LevelMetrics` 和共用弹窗，按赛项、关卡、模式、版本隔离。共用教师指定时段/历史记录筛选，每位玩家展示范围内最近一次成功记录，默认按秒数升序；只显示用时，不显示步数、代码行数或总分，也不套用教师的分数公式。教师端仍能查看和导出记录。

浏览器同时保留个人最快记录作为本地回看。身份键为 `warehouse.player.v1`，当前记录键为 `warehouse.records.warehouse-manual-3.<玩家ID>`。版本 3 对应一箱一格的新布局，旧版本记录保留且不混入新榜单；每条本地记录包含关卡、秒数和完成日期。损坏的本地数据按空记录处理，保存或提交失败会在页面提示。

## 验收

```powershell
npm test
npm run build
npm run test:warehouse
npm run test:leaderboard
npm run test:teacher
```

`npm test` 包含仓储的配置、旋转边界、一箱一格、同格占用冲突与恢复、停稳与送达撤销、必须全部送达、初始物理夹取、不限时和停表测试，并回归已有赛项。

`test:warehouse` 额外运行完整物理路线。参考驾驶器只使用前进、后退、转向、夹取和释放输入，根据实际位置调整行驶。它不修改箱子位置或送达标记，也不证明儿童完成时间或最短路线。计时单元测试中的目的地注入仅用于隔离验证停表逻辑，不作为路线可达证据。

| 验收项 | 预期结果 |
| --- | --- |
| `/home/` 与 `/warehouse/` | 能进入独立仓储赛项，六关可选择 |
| 直接打开并刷新 `/warehouse/warehouse-6/` | 确认玩家后恢复对应关卡，8 箱、8 格、全部送达停表 |
| 开始前按 W/G，完成后按 W/G | 不移动、不改变夹爪状态 |
| 第一关 G 夹取、驾驶、R 放下 | 停稳后计入 1 箱，立即停表，只产生一条成绩 |
| 第二关仅放入一箱、随后放入第二箱 | 一箱不完成，两箱分别入两个格后完成；放进同格无效 |
| 箱子压在边线范围内或旋转后角点越界 | 前者可有效，后者不计为送达 |
| 未抓取释放直接推动进区 | 不计为送达 |
| 已送达箱子重新夹取或移出 | 完成前撤销送达状态，不可重复计数 |
| 第三至六关只送达部分箱子 | 继续计时，最后一箱有效送达才停表 |
| 运行超过 90 秒及 300 秒 | 持续运行，不触发超时失败 |
| 持续按键后窗口失焦 | 清除输入并停止驾驶，实际用时继续累计 |
| 靠墙、接触箱子或夹持转弯后松开转向键 | 制动停稳后朝向保持稳定，不持续自行转动；夹持转弯后仍可正常放下箱子 |
| 重新开始或切换关卡 | 无残留按键、箱子位姿、送达或完成状态 |
| 完成后刷新页面 | 同一玩家的最快及完成记录仍可读取 |
| 完成后打开排行榜 | 服务端显示用时；默认升序，重试不重复新增 |
| 切换指定时段/历史记录或关卡 | 范围和关卡隔离；每位玩家显示范围内最近一次成功记录 |

- `npm test` 通过 99 项，生产构建通过。

- 排行榜 API 测试覆盖仓储成功提交、拒绝未完成/旧版本、重试幂等、用时排序、指定时段与历史筛选、最近一次成功、教师端目录和记录。验证使用临时数据库，未修改线上数据。
- 教师多赛项回归通过，既有赛项的数据与表结构只读检查通过。
