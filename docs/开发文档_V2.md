## 1. 产品与范围

在线浏览器任务，以 DEMO 的“旷野淘金”小车、沙地、金币、路障为视觉背景。用户按“任意拾取 → 给定顺序教学 → 自主找更短路线”学习并完成挑战。

只包含四向单格移动、静态障碍、自动收集金币、路径规划。最后一枚金币到手立即结束，不追加回起点或走到出口的要求。起点离开后仍可通行，途中经过 S 合法。

支持键盘和 Python 填空输入，共用同一地图规则、命令接口和裁判。无实体机器人、3D、能量、攻击、开箱、不同金币价值、步数预算内取部分金币、自由源码 IDE 或 C++ 执行器。DEMO 中存在这些扩展也不能直接带入本次玩法。

### 1.1 关卡数与编号

**20 张地图 × 2 种操作 = 40 个模式关卡。**

- 公共地图 `L01`–`L20`，键盘任务 `K01`–`K20`，Python 任务 `P01`–`P20`。
- Knn 与 Pnn 使用完全相同的起点、障碍、金币与目标，不额外镜像。mode 是独立记录维度。
- 两种模式的任务进度、尝试次数、首轮和最佳成绩分别保存。例如完成 K14 不会自动将 P14 判完成。
- 固定内容入口为 `levels.teacher.json`，含 20 条 levels、40 条 assignments；不得把旧版 7 张示意图充当新题库。
- 金币数量严格按关卡单调不减：01–03关1枚，04–07关2枚，08–10关3枚，11–14关4枚，15–17关5枚，18–20关6枚；任何关卡不得超过6枚。
- 服务器给学生返回白名单投影，隐藏 `expected_optimal_steps`、所有参考解和参考轨迹。

### 1.2 学生群体与测试安排

两批学生分别学过 Python、仅学过 C++。默认都体验两种模式；先键盘理解路线，再进入 Python。C++ 学生增加语法对照和不计分操作练习，正式题目与机会不因此降低。其他分配方式由教师配置，不能根据 cpp 自动剥夺 Python 任务。

完整40关不再承诺在原先40分钟内全部完成。复杂版完整体验按两次组织：键盘20关预留约60分钟，Python20关预留约75分钟（含语法过渡），实测后再调整。这是排期估计，不是已测量用时或淘汰时限。

周三若只有40分钟，默认抽测每种模式的01、04、09、14、15、18，共6关、两模式共12关；约4分钟进入与教学、14分钟键盘、4分钟语法过渡、16分钟Python、2分钟收卷。六关分别覆盖1～6枚金币，其中第09关提供给定顺序教学。课堂时间允许时再增加20关。完整40关仍全部开发可用，抽测只是场次配置；sample14旧配置升级为sample12_v21，不能静默修改已开场分配。未分配关卡记`not_assigned`，不得记未通过或零分。

同题跨模式存在记忆迁移，因此报表分别展示两批学生与两种模式；不能用后做 Python 的用时/分数直接推断模式因果效果或语言能力。若以后做对照实验，应另行设计组间分配和陌生等难题。

## 2. 二十关的递进与教学

| 关卡段 | 任务递进 | 核心观察 |
|---|---|---|
| 01–03 | 单方向、坐标、拐弯 | 方向理解；指令与单格移动对应 |
| 04–06 | 2枚自由拾取、首次绕障 | 收齐与顺序意识；不会因遇障碍退回1枚金币 |
| 07 | 2枚给定顺序 | 分段计步、通过缺口 |
| 08–10 | 3枚给定顺序、多段绕行 | 同顺序路线比较、连续通过通道 |
| 11–12 | 4枚给定顺序、途中金币 | 组合长路线、避开未来目标 |
| 13–14 | 4枚自主规划 | 从固定顺序迁移到自由排序、顺路组合 |
| 15–17 | 5枚、9×9、凹形围墙与双出口 | 区域访问次序、进出成本、减少无效重复 |
| 18–20 | 6枚、10×10、多层复杂通道 | 分组规划与全程优化，最后三关最短35/36/40步 |

复杂度来自金币数、绕障、区域之间的进出与路线选择，不以强迫每关最短步数递增来设计题。保留“先收齐，再改进”的反馈；不要求学生手动枚举6!种顺序或自行实现搜索算法。

每关均有知识点、学生任务、地图、操作说明、反馈和过关条件，见逐关文档。01–06 和 07–12 是学习/练习；13–20 每个模式每关最多 3 轮正式尝试。格式错误在开轮前拦截，不扣机会。

### 2.1 给定顺序的教学必须可操作

07–12 每关提供短、长两条合法示范路线、逐格播放/暂停/重放、下一枚金币提示和一次知识检查。示范走独立 demo 流，不更改玩家轮次、位置或分数。

示范数据在 `solutions.teacher.json` 的 `teacher_demo` 中：短路线是该顺序最短路线，长路线比短路线多 2 步，并已回放验证。L09 专用示范：上4右6下3=13步；上4右4上1右2下4=15步。其他关长路线在起点附近做一次合法往返后再走短路线，便于第一次理解“多走了两格”。

知识检查：“两条路线都按要求捡完了，哪条短？为什么？”答案与修改逐次保存。错误后用格子逐段计数解释。学生关闭演示后亲自完成本关。后续再提问：“如果允许改变顺序，总路程还会变吗？”

L12 要单独解释：要求 A→B→C，但 A 到 B 的直接路线会经过 C，不能按两个端点简单相加。必须考虑途中自动拾取。

### 2.2 自主规划

13–20 开始前输入预计顺序，可选预计步数。预计顺序是计划，不是硬性拾取约束；执行中改变顺序合法，记录真实顺序。每轮开始前都冻结计划修订号。

阶段结束或机会用尽前不显示最优顺序、答案轨迹或“还差几步”。允许看 API、坐标规则与语法卡。教师提供路线时记录 `route_assisted`，不与独立完成混合报告。

L14升级为4枚金币，是“最近的一枚不保证全程最短”的明确例子：最近邻C→B→D→A=21步；B→D→C→A=17步（D→B→C→A也是17步）。该答案只用于教师反馈与裁判。

计划选择器按当前coin_count生成1～6个位置，字母按地图A～F生成；所有金币必须恰好选择一次，不能写死3个下拉框。进度分母、提示列表、排序校验、教师导出均从实际金币数组取值；每次选择、修改和取消继续沿用全量埋点。4～6枚时选择器允许换行，但不得缩小到难以点击。

## 3. 玩家身份与入口

首次进入页面时自动建立随机 UUID 玩家并给出随机称呼，例如“淘金者 Q7M2”。入口显示完整可复制 UUID 和称呼，不要求学生输入姓名。UUID 是稳定的标识，不是密码。所有记录最终必须关联 player_uuid。

正式关卡开始前完成服务器登记。刷新、重开页面、切换模式继续使用同一个玩家；学校换人使用同一电脑时提供“换一位玩家”，确认并保存旧玩家数据后才创建新玩家。不得在每次刷新、每次进入关卡或重来时生成新身份。

入口操作、UUID 生成前的加载节点也要记录，通过 bootstrap 流在登记成功后关联玩家。恢复与鉴权详见专门规格，不能仅凭公开 UUID 读取他人成绩。

## 4. 页面与全部交互

复用 DEMO 的顶部标题/关卡入口、左侧地图、右侧任务说明/状态、开始重来按钮、音效开关与完成反馈的布局语言；加入玩家信息、模式切换、完整关卡导航、计划区、Python 输入区、同步状态。

20 个关卡入口使用分段或可滚动导航，不能把 20 个窄按钮挤在一行。阶段名称和当前位置常驻。最小适配 1024×768，地图格子至少 36 px，代码独立滚动且不遮住棋盘。深色障碍带纹理，金币同时有字母标签，不能仅凭颜色区分。

所有可交互元素必须设置稳定的 `data-track-id` 并出现在交互注册表中：按钮、输入框、下拉项、关卡入口、帮助/提示、音效、棋盘格、方向按键、代码行增删、弹窗确认取消、结果回放、反馈问卷、滚动容器。**功能能用但没埋点视为未完成。**

输入被禁用、无效、重复、超预算或在错误焦点位置触发时，也记录行为与拒绝原因。原始操作与实际移动分别保存，不能把“有按键”误判成“车走了一步”。

### 4.1 学生通用反馈

- 撞墙：“这格有障碍，小车留在原地。换个方向试试。”
- 越界：“到地图边缘了，小车留在原地。”
- 提前拾取：“这次要求先捡 B，你的路线先经过了 C。看看可以怎样避开它。”
- 收齐：“金币收集完成，本轮走了 X 步。无需返回。”
- 待同步：“已保存在这台电脑，等待同步。”
- 已确认：“已同步。”仅在服务器完整性确认后显示。

## 5. 统一规则内核

所有规则与 V2 JSON 一致，不照搬 DEMO 游戏状态逻辑。

1. 原点左下，x 向右、y 向上；屏幕行号 `row=height-1-y`。只允许 up/down/left/right 单格移动，无对角线与朝向成本。
2. 键盘有效按键或代码一次函数调用产生一条标准命令，`command_index` 从 1 连续递增。动画只显示内核结果。
3. 撞墙/越界：位置不变，命令数和碰撞数+1，成功步数不加。继续接受下一条命令，不自动修正路线。
4. 进入未收集金币格立即拾取一次，移除该金币；再次经过不重复得分。本版不需要在金币格停留 1 秒。
5. 给定顺序关提前捡到非下一枚金币时，先如实记录成功移动与拾取，再终止为 `order_violation`，不假装金币是墙或拒绝拾取后让车继续。
6. 无顺序限制关以真实拾取顺序为准；所有金币收齐立即 `success`，丢弃后续输入队列，不返回起点。
7. 每轮最多 256 条尝试命令，包括碰撞。第 256 条先判错误顺序/成功，再判预算耗尽；未成功则 `command_limit`。
8. 教师可查看多种参考路线；学生只要合法收齐且步数最短即可最优，不匹配固定答案字符串。

```ts
type MoveCommand = {
  command_id: string;
  command_index: number;
  direction: 'up'|'down'|'left'|'right';
  source: 'keyboard'|'python_blank';
  interaction_id: string;
  source_row_id?: string;
};
// 纯函数，不读取 UI、网络或系统时间。
step(state, command, rules): { next_state, domain_events };
```

状态提交顺序：验证轮次/命令 → 边界/障碍 → 更新位置和步数 → 自动拾取 → 顺序检查 → 收齐检查 → 命令预算 → 原子提交事件。网络重传同一命令不能重复移动。

### 5.1 轮次与编辑状态

`draft → running ↔ paused → success | incomplete | order_violation | stopped | abandoned | command_limit | expired`。

draft 尚未开轮；校验失败停留在 draft。开始/运行/单步先取得服务端 attempt_id 才扣一次正式机会。代码耗尽没收齐为 incomplete，玩家停止为 stopped，重来保留旧轮为 abandoned；终止后不能修改原轮继续运行。

编辑发生在 assignment 的草稿流；每次开轮冻结 program_revision 与 plan_revision。单步和连续运行可在同一轮切换。刷新恢复未结束轮继续同 attempt，不扣机会；两标签页同 assignment 只允许一个 writer_token。

同步状态独立于玩法状态：`local_pending → uploading → verified | needs_review | rejected`。成功动画不等于已收卷。场次截止由服务器管理，已开始的离线轮次在截止后补传记待审核，保留证据并由教师确认。

## 6. 键盘与 Python 的输入规范

### 6.1 键盘

方向键、WASD 和四向按钮都是绝对地图方向。一次有效 keydown 尝试一格；重复 keydown 不再派发命令，但每个观察到的重复事件仍埋点。keyup 也记录，用于计算持键时长。按键速度不参与分数。

仅棋盘聚焦时派发移动；输入框内按方向键用于编辑，记录为编辑上下文，不移动小车。失焦清空 held-key 集合，暂停未派发队列；恢复可继续或清空尚未派发队列，不能撤销已执行动作。队列不因动画忙碌丢弃有效输入，最多本轮剩余命令额度。

点击和触控方向按钮的 pointer/click 都保存，但只在统一 activate 点派发一次动作，不能一次点击走两格。动画默认 160 ms/格，视觉车头可按 DEMO 转动，不产生独立转向指令或改变步数。

### 6.2 Python：明确哪些能输入

**每关可编辑区域在逐关文档和 JSON 的 `python` 中明确列出，不允许整个编辑器自由输入。** 初始空格为空；固定代码灰底只读；输入框白底、有焦点边框与中文说明。

| 范围 | 学生可输入 | 固定代码 | 允许的代码 |
|---|---|---|---|
| P01–P03 | 每行 direction 空：up/down/left/right | move_、括号、行数 2/3/5 | 四个无参数移动函数 |
| P04 | 每行 direction 空，可增删 1–32 行 | move_、括号 | 四个无参数移动函数 |
| P05–P12 | 每段 direction 和 count 两个空，可增删 1–24 段 | for、range、冒号、缩进、move_、括号 | 四个移动函数 + 固定 range 重复结构 |
| P13–P20 | 同上，独立决定所有方向与次数 | 同上；不预填路线或目标顺序 | 同上，不提供自动规划函数 |

direction 接受英文小写白名单，提供中文下拉建议但也可键入；输入 `move_up()` 到方向空要提示只填 `up`。count 接受 0–20 的十进制整数，不接受负数、小数、科学计数法、表达式、空白；0 跳过该段，整个程序必须至少 1 步且最多 256 步。

四个函数为 `move_up()`、`move_down()`、`move_left()`、`move_right()`；无需 `pick_up()`。不开放 `move_to`、变量、if、while、import、嵌套循环、任意表达式。题目考察路线和指令组合，不要求学生编写 BFS。

程序参数经白名单校验后生成合法 Python 供阅读/导出，并展开成标准命令执行。不要用 eval/exec 执行学生文本；这是封闭模板模式，不宣传成完整 Python 解释器。

```json
{
  "template_id": "repeat_slots_v2",
  "program_revision": 12,
  "rows": [
    {"row_id":"row-uuid-1","direction":"right","count":3},
    {"row_id":"row-uuid-2","direction":"up","count":2}
  ]
}
```

`call_slots_v2` 行结构只包含 row_id、direction，count 字段不可额外注入；`repeat_slots_v2` 才有 count。服务器按 assignment 锁定模板和行数范围，不能让客户端换模板绕过该关输入边界。展示源码不作为执行证据。

运行中锁定编辑；单步每次一条单位命令，并显示所在行/段及第几次重复；停止后保存已执行前缀，新编辑需新开轮。运行按钮、所有字段输入、验证失败、行号高亮结果、停止和重试都有埋点。

服务器重新展开冻结的模板，验证提交命令等于合法执行前缀；提前终止只允许收齐、停止、预算、截止等合法原因。不能上传任意正确轨迹冒充自己写的代码。

### 6.3 C++ 学生过渡

P01 前说明四个函数的作用，所有学生做同一方向输入热身。P05 前用以下中性示例解释循环，C++ 组展示对照，Python 组可折叠查看：

```cpp
for (int i = 0; i < 3; i++) {
    move_right();
}
```

```python
for _ in range(3):
    move_right()
```

说明“两段都重复向右三次；Python 冒号和缩进已经替你写好”。对照卡打开、停留和关闭均记录；它不是路线提示。

## 7. 最优解与判分

自由顺序BFS状态`(x,y,collected_mask)`，每条成功移动成本1，走到金币即更新mask，首次收齐为最优。给定顺序另要求每次新拾取符合前缀，经过未来金币的分支不能成为合法解。最多10×10、6枚金币，最多100×2^6=6400个自由搜索状态，收齐目标mask为`(1 << coin_count) - 1`，不能写死7。

必须用精确可通行图求解，不能用 DEMO 的曼哈顿顺序求和或最近邻作为带障碍裁判。枚举真实顺序并逐个约束搜索，最小值应等于自由 BFS。L12 的自由最优与固定顺序最优不同，判分按该关 fixed order 值。

6枚有720种候选顺序；20关合计2645种候选顺序在内容发布时校验。此工作只在构建/发布内容时进行，正式移动和输入过程中不重复枚举；服务端裁判使用对应地图版本缓存的最优值并重放实际命令。

01–12 记录收齐/步数/顺序/帮助，作为学习过程。13–20 每模式每关最多 3 次，独立展示：

```text
收集分 = 60 × 已收集唯一金币数 / 总金币数
路线分 = success ? 40 × 本关最短步数 / 成功移动步数 : 0
总分 = 收集分 + 路线分
```

展示1位小数，保留全精度。L14成功17步=100分，成功21步≈92.4分，只捡3/4枚=45分；6枚关只捡4/6枚=40分。碰撞、语法错误、用时分列分析，不重复扣路径分，不用速度破同分。

最佳轮次先比较成功；成功轮取步数最少；均未成功取收集数最多；同分保留较早轮作代表且可同名次。首轮不能被最佳覆盖。只有两轮都成功才计算少走多少步；帮助过的结果单列。成功步数小于裁判最优值属于异常，转 needs_review，不能截为100分掩盖问题。

不同模式、不同语言经历、已见过题与未见过题分别统计。试测不从一次路线成绩直接诊断学生创造力或认知能力，也不跨模式简单合成排行榜。

## 8. 开发架构与线上接口

在工作区新建 `coin-path-pilot/`，不要覆盖 DEMO。React + TypeScript 学生/教师界面；独立 TypeScript 规则与模板模块；Node 服务端持久化，默认单实例 SQLite 持久磁盘与备份；部署无持久磁盘则用 PostgreSQL。依赖与命令实际锁定并测试，不以既有演示刷新可用替代在线系统。

```text
键盘适配器 / Python 填空编译器
              ↓ 标准命令
          纯函数规则内核 → 已提交状态 → DEMO 视觉组件
              ↓ 领域事件
     全量交互记录 + 事件事务 → IndexedDB → 批量上传
              ↓
服务器绑定身份 / 版本重放 / 完整性核对 → 权威成绩 → 教师导出与回放
```

数据库至少有 players、sessions、enrollments、assignments、task_versions、attempts、event_streams、events、teacher_actions。事件 ID 唯一、(stream_id,seq) 唯一；轮次绑定 player_uuid、assignment_key、content/rules_version、trial_index、writer_token 和程序快照。保存原始输入事件，不只保存最后代码和成绩。

### 8.1 接口清单

| 接口 | 要求 |
|---|---|
| `POST /api/players/bootstrap` | 自动创建/恢复 UUID 玩家、随机称呼、安全会话；幂等，细节见身份文档 |
| `POST /api/players/switch` | 保存旧流后切换新玩家，隔离历史，不删除旧成绩 |
| `PATCH /api/players/me/profile` | 修改语言/经验区间，服务器绑定身份；记录修改事件 |
| `POST /api/join` | 仅需场次码 + 现有玩家会话；返回该场次分配的模式和关卡 |
| `GET /api/assignments/:id` | 学生版地图、模板输入边界、剩余次数、已有轮次，不含答案 |
| `POST /api/attempts` | assignment_id、idempotency_key、计划快照；Python 另传程序快照；返回 attempt_id 与 writer_token |
| `POST /api/event-streams/:id/batches` | 统一接收 bootstrap/player/assignment/attempt/system 流；批量去重，返回连续确认与缺段 |
| `POST /api/attempts/:id/finalize` | 已执行命令、原因、最终seq、相关流高水位、快照引用；服务器独立重放与完整性检查 |
| `GET /api/attempts/:id` | 查询 verified/pending/needs_review 与成绩、缺失范围 |
| `POST /api/teacher/login` / `POST /api/logout` | 教师鉴权和退出；不开放学生成为教师 |
| `POST /api/teacher/sessions` | 创建场次、选择 full40 / sample12_v21 / 自定义完整题库子集、时间与容量；绑定2.1内容包 |
| `POST /api/teacher/sessions/:id/control` | 开场、截止、延期，审计原因 |
| `GET /api/teacher/sessions/:id/progress` | 按玩家/模式/关卡看进度、待同步、异常与日志完整度 |
| `GET /api/teacher/sessions/:id/export?format=csv|jsonl` | 逐轮、逐关、玩家汇总与全部原始事件 |
| `GET /api/teacher/attempts/:id/replay` | 服务器轨迹、代码修订、指令、碰撞和同步状态 |
| `POST /api/teacher/assignments/:id/grant-attempt` | 故障补机会，关联原 attempt、教师、原因 |

UUID 不当访问凭证。所有接口以安全会话校验归属；教师才可全场查看。重复开轮/提交不能重复扣机会或写成绩；超时请求重用幂等键。字段非法422、归属错误403、双写/版本冲突409、限速429、服务错误5xx给可重试标记。

同源 HTTPS；玩家与教师 Cookie 隔离权限。初始化教师用一次性部署命令，密码只存哈希。身份、学生数据、API 响应不进公共共享缓存；版本化贴图和前端资源可缓存。禁止真实秘钥、学生数据放进源码或模板。

## 9. 保存与教师收卷

逐个交互先写本地可靠事件队列；内核命令、状态和派生事件在同一事务提交；网络按批上传，不逐键请求。不能因防抖、限频、重绘或动画忙碌静默丢事件。完整细则见埋点文档。

正式开轮必须在线取得 attempt_id；开始后断网允许本机继续并标注待同步，离线不能新开正式轮。刷新恢复同一未终止轮；本机存储失败时暂停正式输入并报告。技术故障由教师补机会，保留原始记录。

教师收卷页分别显示：玩法完成、命令判分已验证、交互日志完整、仍待同步。缺了任何要求流的事件，不能给出“日志完整”或“全场已收卷”。数据不齐时保留临时成绩，但最终正式确认等待补齐或教师审计。

CSV 一轮一行：player_uuid、display_name、session_id、mode、level_id、assignment_key、语言经历、content/rules版本、attempt_id、trial_index、状态、收集数、步数、最优值、碰撞、预计/实际顺序、首轮/最佳、分数、计划/执行/暂停/离开时长、帮助、同步与日志完整度。另有逐关分配/未开始/跳过/完成汇总，未分配题不记零分。

JSONL 保留所有原始事件 envelope、业务 payload、服务器接收时间。回放支持棋盘逐格与输入修订时间线，不依赖最终截图。保持 UTF-8，CSV 文本字段不允许解释为公式，学生文本按纯文本渲染。

默认明细保留30天，可按学校安排配置；随机身份不额外要求姓名、手机号、影像。身份对照由学校自行保管，不用浏览器指纹或硬件信息关联玩家。
