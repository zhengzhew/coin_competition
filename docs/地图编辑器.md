# 测试赛地图编辑器

启动前端后，在 `/demo/` 展厅点击“地图编辑器”，进入 `/demo/showcase/map-editor/experience/`。也可从组件库“棋盘地图编辑器”进入。详情提供体验、规则、技术方案、版本与复用四个栏目。

独立 `/editor/` 和教师端入口继续可用，与 DEMO 复用同一个编辑器及同一份本机草稿；可从体验页点击“独立打开编辑器”。编辑器无需教师密钥，不读取学生数据。

## 快速制作

1. 选择“旷野淘金”或“未来城市”。可以新建空白地图，也可以载入现有的 20 张淘金地图或 6 张未来城市巡逻、配送地图（FL31–FL36）。
2. 选中左侧工具，点击地图格子放置元素。起点只有一个，选择起点工具点击其他格子即可移动。机器人货物与泊位使用同一字母配对，重复放置同字母元素会移动它。
3. 在元素工具区点击“上、右、下、左”设置小车初始方向，起点箭头同步更新。机器人按此方向前进或后退；淘金模式的移动仍按绝对上下左右方向。按需修改宽高、名称、任务说明和收集规则。坐标原点在左下角。平台高度仅控制配置中的视觉高度，试走沿用当前测试赛的网格规则。
4. 点击“检查地图”，再点击“开始试走”。试走按钮使用两场比赛现有的共享规则引擎，不记录正式成绩。
5. 点击“导出地图”保存 JSON；以后可以通过“导入 JSON”继续编辑。

## 保存与边界

- 草稿自动保存在当前浏览器的本机存储中；清理浏览器数据会丢失草稿，建议及时导出备份。
- 撤销与重做最多保留 50 步编辑历史，刷新或离开体验页后历史不保留，地图草稿仍可恢复。新建、切换测试赛、载入模板和导入均可撤销。
- 宽度 3–24 格，高度 3–16 格，最多 8 个目标。尺寸可直接输入，回车或移开焦点后应用。缩小时自动裁剪界外元素，起点超界时移回地图内；扩大时为新增区域补平台，保留原区域内的空洞。调整可以撤销恢复。若泊位被裁掉而货物仍保留，需要重新配对。大地图可在画布区域横向滚动。
- 淘金地图支持金币（1 分）、宝箱（3 分）、障碍、自由或按放置顺序收集，以及成功移动步数上限。
- 机器人地图支持平台、平台高度、障碍、货物、泊位和车头朝向。橡皮擦会移除该格元素及平台；放置起点、障碍、货物或泊位会自动补上平台。
- 两种地图均支持“打卡点（金币）”。小车进入该格即完成一次，不需要夹取、松开或配对泊位。打卡点与货物共用 A–H 目标编号，最多 8 个目标。机器人地图必须到达全部打卡点并送达全部货物才通关，也可以只设置打卡点。
- 初始方向和打卡点会随草稿、JSON 导出及导入保留。打卡点以 `coins[].type: "checkpoint"` 保存；机器人方向使用 `robot.facing`，普通地图方向使用 `initial_facing`。
- 机器人起点可以兼作回程打卡点，离开后重新到达时才计入。模板的 `robot.checkpoint_order` 会在页面显示，并随刷新和导入导出保留；删除或裁剪打卡点后自动移除对应顺序项，新增打卡点追加到顺序末尾。
- 淘金检查可求出收齐目标的最短步数；限步地图可能无法在预算内收齐，仍可用于取分任务。机器人仅做结构校验，需要人工试走确认可通关。
- 只接受范围内整数坐标、A–H 唯一目标字母等有效配置。结构不完整的草稿可以继续编辑，但不能试走或导出。

## 配置接入

导出文件是单张 `LevelDef` JSON，使用独立的 `CUSTOM01 / CUSTOM_K01 / CUSTOM_P01` 默认编号。导出会清除过期答案字段，淘金地图重新计算收齐最短步数。

当前正式比赛仍使用固定关卡配置和任务编号白名单。导出不会自动发布或替换比赛地图；正式使用前需分配唯一任务编号、配置版本，并更新关卡加载和任务白名单。不要用旧编号直接覆盖已有学生记录对应的关卡。限步最高价值等教师答案需要在正式接入时重新生成。

导入可接受单张地图或包含 `levels` 的关卡包（取第一张），并规范化为编辑器支持的字段，不作为完整关卡包的无损编辑工具。

DEMO「版本与复用」中的“下载示例配置”导出组件依赖及 `{ embedded: true }` 嵌入配置。实际地图仍从编辑器工具栏“导出地图”下载。当前只支持棋盘地图，不是连续物理 3D 场地编辑器。

需要在其他项目页面复用时，引用 `client/src/MapEditor.tsx` 并渲染 `<MapEditor embedded />`；不传 `embedded` 时使用独立页面布局。模型校验集中在 `client/src/map-editor-model.ts`，试走使用共享规则引擎，两处入口不会维护各自的编辑器副本。

## 验证

运行 `npm run test:editor:browser`（构建后执行 `scripts/verify-map-editor.mjs`）。如 Playwright 不在项目依赖中，通过 `PLAYWRIGHT_MODULE` 指向已有的 Playwright 包。

验证包括展厅筛选入口、组件库入口、详情栏目直达与历史导航、独立入口草稿共享、两种规则试走、点击放置、尺寸裁剪与扩展、撤销重做、本机恢复、JSON 下载与导入、错误导入保护、配对校验，以及桌面、768px 平板和 390px 小屏幕布局；检查不调用比赛 API。截图及结果位于 `outputs/map-editor/`。
