# DEMO 展示中心开发说明

## 本地体验

按项目原有方式运行 `npm run dev`，访问 `/demo/`。生产构建执行 `npm run build`，启动服务后同样访问 `/demo/`。

开发预览地址为 `http://localhost:5173/demo/`，对应后端为本机 3001 端口。测试预览可通过 `COIN_DATA_DIR` 使用独立数据目录；普通 `npm run dev` 使用项目默认数据目录。

2026-10-08 起，本模块作为持续扩展的 DEMO 展示中心，不再使用“第三子赛项”作为页面名称。原 `/third/` 入口及关卡深层地址已移除，生产服务返回 404，不保留跳转。

`client/demo/index.html` 为唯一 DEMO 页面入口。内部机器人适配仍保留 `third` 代码目录、样式标识、内容 ID 及 `third.program.*` 草稿键，避免丢失既有草稿。通用内容注册在 `shared/src/gameplay/catalog.ts`，展示中心名称和目录不再绑定赛项编号。

展厅提供四个机器人 DEMO（收集／摆放 × 棋盘／3D，各支持自动与手动，共 8 个组合）、一个交互计分 DEMO 和地图编辑器。所有 DEMO 都不提交正式成绩。组件库展示机器人运行控制、城市棋盘场景、完成度与效率计分、棋盘地图编辑器四项能力。

地图编辑器位于 `/demo/showcase/map-editor/experience/`，按需加载已有 `MapEditor` 组件，通过 `embedded` 属性适配展厅布局。独立 `/editor/` 保留，两处共享 `competition-map-editor-v1` 本机草稿；切换详情栏目后重新进入可恢复地图，撤销历史仅在组件挂载期间保留。规则、技术与复用说明同样由通用目录注册，编辑器作为 `map-editor@development` 能力展示。体验页导出的是地图 `LevelDef` JSON；版本页下载的是编辑器嵌入配置，二者分别说明。编辑器目前支持淘金与未来城市棋盘，不支持连续物理 3D 地图编辑，也不直接发布赛事配置。

操作方式在分类入口选择，进入关卡后固定，关卡内不提供手动／自动切换。要体验另一种操作方式，先返回分类，再重新选择入口进入。刷新仍保持当前入口的操作方式。

棋盘与 3D 关卡共用未来城市的页面布局和样式：顶部状态栏、左侧关卡导航、中间任务与场景、右侧控制区。棋盘直接使用既有 `CityBoard3D` 场景组件呈现格子规则；3D 使用本地比赛沙盘，并沿用相同的视角工具栏和控制区布局。

连续物理 3D 的自由视角支持左键旋转、右键或 Shift + 左键平移、滚轮缩放；点击“平移”后左键或单指拖动也可移动焦点，俯视模式默认拖动平移。双指支持平移与缩放。“跟随小车”将焦点锁定在小车上，允许绕车旋转和缩放；小车移动时相机同步位移，保留观察角度与距离。窗口尺寸与全屏变化保留当前焦点，点击“复位”恢复地图全景。生态农场直接复用同一场景组件与相机操作。

3D 场地依据用户提供的比赛沙盘截图方向制作，模型及地面纹理在本地生成。机器人按连续位置运动；地面的印刷标线不是逐格移动约束。

## 玩法展示与赛事组件来源（2026-10-08）

### 产品定位

DEMO 中心同时承担两项职责：展示各种玩法和规则；沉淀赛事可以直接引用的技术实现。展示页面、共用能力和具体赛事分开组织，DEMO 与赛事通过代码依赖复用能力，避免分别复制一套实现后维护。

现状：通用注册目录、筛选展厅、组件库、详情栏目和配置下载已实现。机器人控制已提取为共享运行模块；未来城市实际计分与计分 DEMO 共用固定的 `completion-efficiency@1.0.0`。机器人及城市场景组件仍为 development，3D 外观仍绑定农业场地，不宣称它们已具备正式赛事的版本隔离。

### 三层组织

| 层次 | 职责 | 示例 |
|---|---|---|
| DEMO 展示 | 让人体验玩法、理解规则、比较方案、查看能力的使用示例 | 自由推块、夹爪搬运、按序收集、限时任务 |
| 共用能力 | 提供可配置、可测试、可被多个入口引用的实现 | 棋盘场景、连续运动、夹爪与碰撞、任务判定、指令编辑器 |
| 赛事实例 | 选择能力并设置赛事专属内容，接入正式比赛流程 | 地图、车型参数、任务、计分、次数、身份、成绩提交 |

一个能力可以由多个 DEMO 展示；一个 DEMO 或赛事可以组合多个能力。玩法标签、所属赛事和技术能力是不同维度，不能把“收集／摆放”当作所有未来 DEMO 必须遵循的目录结构。

### 展示中心的内容结构

- 首页按主题和能力展示 DEMO，支持玩法类型、操作方式、表现形式和成熟度筛选；只展示该 DEMO 实际支持的方式。
- 每个 DEMO 有稳定 ID、名称、简介、状态、标签和独立体验地址。现有机器人入口继续可用，新增主题不再要求修改收集／摆放枚举。
- 详情包含“体验”“规则”“技术方案”“版本与复用”：默认进入体验，技术细节留在相应栏目。
- “规则”展示目标、操作、成功与失败条件、计分示例和边界情况，做到规则说明与运行效果一致。
- “技术方案”列出使用的能力、可调参数、输入输出、限制和最小接入示例；可查看哪些赛事使用了该版本。
- 初期采用代码中的注册目录与配置文件维护，不把在线代码编辑器、任意脚本上传或完整低代码搭建器作为前置条件。

### 首批可复用能力及边界

| 能力 | 接收的配置 | 提供的结果 |
|---|---|---|
| 棋盘及 3D 场景 | 地图、对象、主题、相机 | 场景渲染；不自行提交成绩 |
| 移动与物理 | 尺寸、速度、碰撞、摩擦、夹爪参数 | 位置与物体状态、接触事件 |
| 操作与程序执行 | 按键映射、指令集合、执行限制 | 统一的操作命令和执行状态 |
| 任务规则 | 收集顺序、目标区域、完成条件、时间限制 | 任务进度、成功或失败、判定原因 |
| 计分规则 | 权重、扣分、封顶规则、规则版本 | 可解释的成绩结果；正式赛事仍由服务端核验 |
| 玩法工作区 | 场景、控制器、任务和反馈模块 | 组合后的交互页面 |

先保留棋盘、平面物理等运行方式各自的状态类型，通过显式适配器连接，不把所有场景强塞进同一个坐标或碰撞模型。距离单位、时间步长、启动／停止／重置／销毁及事件格式必须明确；场景外观与任务判定分离。

共用能力不依赖 DEMO 首页、具体赛事名称或比赛数据接口。DEMO 使用本地试用配置；赛事通过适配层接入身份、正式次数、服务端核验、成绩和埋点。演示状态不得写入正式比赛记录。

### 修改与复用的关系

1. 修改共用能力代码，DEMO 立即用于预览和验证；接入该能力的赛事可采用这项改进，无需重复修改一套代码。
2. 修改某个 DEMO 的地图或参数，默认只影响该 DEMO。需要复用时将其保存为具名配置预设，由赛事显式选择。
3. 改动先在样例中验证，再产生可复用版本；正式赛事明确选择升级版本，不能默认追随试验中的实现。
4. 单纯添加 `version` 字段不能隔离代码变化。正式版本需要对应可重现的代码／构建产物，例如不可变版本包或固定提交构建的赛事产物，同时记录组件版本、配置版本和内容版本。
5. 回放或核验历史成绩时使用当时的规则版本；有计分影响的升级必须保留旧版本的核验依据。

例如：在 DEMO 中改进夹爪接触判定并形成新版本后，多个使用夹爪的赛事可分别升级；各赛事的地图、货块数量和得分设置仍由自己的配置决定。

### 实施顺序与验收

1. **通用展示目录**：建立不依赖 `competition_id: 'third'` 的 DEMO 元信息目录，将现有样例作为第一批内容注册。新增一个不同类型的 DEMO 时无需扩展收集／摆放分支，已有入口和关卡固定操作方式继续有效。
2. **首个完整复用单元**：整理现有机器人样例的运行接口、场景接口与配置校验，沿用已经存在的棋盘／3D 适配实现；DEMO 页面只负责组合和展示。验证自动、手动、重置、输入释放、页面退出与资源回收。
3. **赛事接入验证**：选择一个规则匹配的赛事实例接入共用能力，使用不同地图或主题配置，证明两处引用同一实现；保留赛事原有计分、身份和服务端核验行为。其他正在开发的页面不在本次方案阶段修改。
4. **版本与使用记录**：在正式接入前落实可重现版本和依赖记录，展示组件被哪些 DEMO／赛事使用，完成升级与回退验证；演示版修改不能改变已固定版本赛事的规则或历史核验结果。

当前完成通用目录、首批共享能力和首个正式赛事计分接入。首个不可变发布版本为计分组件 1.0.0；后续新增版本时保留旧目录、旧指纹及对应配置，显式调整赛事绑定，不使用 latest。其他开发中能力需经过同样发布流程再用于固定规则的正式比赛。新旧计分规则并存时，还需在比赛记录中持久化对应版本并建立历史核验映射；当前未来城市保持原有计分语义，尚未切换到第二个计分版本。服务器继续由既有自动部署脚本负责。

增加一种 DEMO：在通用目录提供唯一 ID、renderer、配置、规则、能力依赖和技术说明；如果是新的表现方式，在客户端 renderer 注册表接入一个体验组件。机器人已有的八种组合通过适配器接入，不要求其他类型声明 collect/place 或 auto/manual。

下载配置使用 `{ schemaVersion, demoId, contentVersion, components, configuration }`。计分体验中可修改分值并下载当前配置；机器人详情可下载样例配置。在接入代码中显式检查组件版本，再将 configuration 传入对应组件。下载不会直接更改赛事文件。

```ts
// 同一计分实现：DEMO 可传演示配置，未来城市绑定默认 60/20/20。
scoreWithRelease('1.0.0', evidence, preset.configuration);

// 机器人场景与运行实例隔离，外部配置修改不影响已运行的实例。
const runtime = createRobotRuntime(preset.configuration, 'auto');
runtime.start(preset.configuration.starter);
runtime.tick(1 / 60); // 单位：秒；控制帧由调用方调度

runtime.stop();
runtime.reset();
runtime.dispose(); // 释放后不可再次启动
```

不要修改已有 `v1/policy.ts` 或覆盖其指纹来改变规则。增加新版本实现及对应指纹、解析入口和验证用例，再按赛事选择升级；回退时重新绑定仍然保留的旧版本。第一次发布仅有 1.0.0，没有伪造的历史版本。

## 3D 物理尺寸（2026-09-26）

- 地图有效区域 120 × 120 cm，10 × 10 格，每格 12 cm；围栏在有效区域边缘。
- 左下角为 (0, 0)，向右 X 增大，向上 Y 增大。界面显示车体中心坐标，单位 cm。
- 车体（含轮子投影）19 × 19 cm；前端夹爪整体宽 19 cm、伸出长度 6 cm，车体和夹爪总长 25 cm。
- 货块占地 6 × 6 cm；展示高度暂取 6 cm。夹持中心位于车体中心前方 12.5 cm，两侧夹指会随夹取收拢。
- 移动指令使用厘米，支持大于 0 且不超过 120 cm，默认移动速度 18 cm/s；转向仍使用角度，等待仍使用秒。测量网格不限制连续运动。
- 内部 Three.js 使用向下的 z 坐标（单位同为 cm）；显示坐标为 `(x, 120 - z)`。地图、渲染和碰撞共用 `geometry.ts` 中的尺寸常量。
- 3D 摆放使用 Planck 平面刚体物理，车体、两侧夹指、货块均有独立碰撞体，货块可平移、转动、连推和滑脱；开启连续碰撞检测，内部以至多 1/120 秒推进。夹爪中间为空，不使用整块实体包络。
- 夹持由两侧夹指接触判定，不使用距离吸附或固定连接。目标区为 12 × 12 cm 方框，货块全部四角进入、脱离夹持并低速停稳 0.4 秒后计入；离开后取消到位，所有目标同时成立才完成。物体不自动对齐中心。
- 3D 内容版本更新为 `sample-contact-3`；旧版本草稿保留在原存储键中，新版载入接触物理示例。

## 操作

- 手动：点击“开始控制”，W/S 前后移动，A/D 相对车头转向，也可用方向键。棋盘每次按键走一格或转 90°；3D 按住连续运动，物理摆放中松开会制动减速。
- 3D 摆放：G / `grab()` 合拢夹爪，R / `release()` 张开夹爪。没有货物也能空夹；对准后双侧接触并靠摩擦夹持，碰撞、转弯和斜夹可能导致滑脱。棋盘摆放继续使用原有夹取／放下规则。
- 自动：编辑指令或点击指令面板添加；点击运行从初始场景执行，停止随时可用。
- 重置：恢复机器人、物体及目标进度，保留编辑器中的程序。
- 离开关卡或失焦会停止运行；返回分类后重新进入会创建新的运行实例。3D 场景不可用时显示重试入口。

指令语言是受限命令集，不执行任意 Python 或 JavaScript：

```python
grab()
forward(24)
turn_right(90)
forward(30)
turn_right(90)
release()
```

支持 `forward(n)`、`backward(n)`、`turn_left(角度)`、`turn_right(角度)`、`wait(秒)`。摆放任务额外支持 `grab()`、`release()`。支持 `for i in range(n):` 或 `for _ in range(n):`，每层缩进 4 个空格，最多两层循环。棋盘距离为整数格数、转角为 90° 倍数；3D 的距离统一使用厘米（上述程序为 3D 摆放示例）。

程序最多 150 行、8000 字符、256 条展开指令，单轮最长 120 秒。浏览器本地只保存各 DEMO 独立的程序草稿；存储不可用时仍可操作，但页面会提示草稿未保存。

### 3D 精准定位（2026-10-08）

3D 编程支持普通移动与精准定位混用。棋盘的手动和自动仍按整数格移动，不接受精准定位或按秒移动指令；3D 手动仍连续驾驶。对外指令统一为 `move_to`、`turn_to`，已有本机草稿会自动转换旧指令名。

| 指令 | 含义 |
|---|---|
| `move_to(x, y)` | 将车体中心移到绝对坐标；X、Y 使用整数厘米，当前地图各为 0–120。先原地转向目标，再直行到点。 |
| `turn_to(angle)` | 原地转到绝对朝向，取最短转角；接受 0–360°，360° 等于 0°。 |
| `forward(cm)` / `backward(cm)` | 沿当前车头方向前进／后退指定厘米数，使用普通速度。 |
| `forward_time(seconds)` / `backward_time(seconds)` | 使用普通速度前进／后退指定秒数，可填小数。 |

地图左下角为 `(0, 0)`，向右 X 增大、向上 Y 增大；0° 朝地图上方，90° 向右，180° 向下，270° 向左。显示与指令以车体中心为准，渲染内部坐标为 `(x, depth - y)`。

精准定位直行和旋转速度均为对应普通速度的 50%，由 `THIRD_OID_SPEED_FACTOR` 统一定义。默认普通速度 18 cm/s、90°/s，精准定位为 9 cm/s、45°/s；程序预计时长计入预转向与半速行驶，并沿用 120 秒限制。

定位模拟理想的反馈，连续运动到目标后消除数值积分残差，精确停在指定中心坐标与朝向。等待、夹取和松开期间保持该定位；后续普通移动或相对转向会退出保持。碰撞、夹指接触、货块摩擦仍生效，不通过瞬移车体或货块完成定位。遇到障碍或车体／夹爪无法容纳的边界位置会停止并提示受阻，不自动规划绕障路线。当前实现不连接实物定位设备。

3D 摆放样例可以使用：

```python
grab()
move_to(54, 48)
turn_to(90)
move_to(84, 48)
turn_to(180)
release()
wait(1)
```

编辑器提供移动到点、转到角度、普通距离和时间按钮；地图下方显示实时车体中心与朝向，精准定位面板显示目标和到位状态。收集任务会走完当前定位指令后再结束，避免进入收集半径就提前停车。

### 共用小车模型（2026-10-08）

连续 3D、城市棋盘和草莓农场棋盘统一使用用户提供的 `000_saikao.obj` 底盘，通过 `client/src/components/SaikaoRobot.ts` 加载本地 `/assets/robots/saikao.glb`。模型只负责外观，运动、碰撞和任务判定仍由各模式的规则引擎处理。

原 OBJ 约 108 MB、27,190 个网格、525,062 个三角面。离线转换后合并为 26 个网格、119,953 个三角面，GLB 约 4.2 MB；网页不解析原始大文件。转换脚本为 `scripts/prepare-robot-model.mjs`，运行时传入源 OBJ 的路径。同目录 `saikao.json` 记录源文件 SHA-256、转换方式、网格规模和尺寸，便于重现。

根据既定 19 cm 车长，将原模型坐标按毫米解释并等比缩放到厘米；底盘外形约 17.89 × 19 cm，高 7.72 cm，放入既有 19 × 19 cm 车体碰撞范围。源 Z 轴改为向上，源 Y 正方向作为车头，对齐场景 -Z；车体中心、朝向和地图坐标共用原来的定位基准。棋盘按单格展示比例缩放，轮子落在格面上。

OBJ 未附 `000_saikao.mtl`，当前使用中性色基础材质。源模型不带比赛夹爪，仍单独挂载宽 19 cm、长 6 cm 的可动夹爪，开合位置来自运行状态。加载失败采用场景原有的重试或轻量地图机制；加载中退出会释放模型，各场景独立释放 GPU 资源，缓存只保留模型文件字节。

## 增加 DEMO

1. 在 `shared/src/gameplay/catalog.ts` 注册通用 `DemoManifest`。机器人示例提供 `RobotScenario` 配置；其他类型使用对应组件的配置，不依赖机器人分类。
2. 为每个内容提供稳定的 `demo_id` 和 `content_version`；正式规则或布局变化时更新版本。
3. 声明类别、模拟形式、开放状态及支持的操作方式；未实现的内容使用 `planned`。
4. 配置初始位置、目标、障碍及示例程序。棋盘复用现有规则，3D 的连续运动由 `ThirdEngine` 处理。
5. 当前 3D 渲染使用农业比赛场地；如新增布局或主题，需要同时修改 `simulation3d/farm-arena.ts` 或新增对应场景构建器，确保可见道具与碰撞配置一致，不能仅修改障碍数组。
6. 分别从自动、手动入口使用程序与真实按键完成任务，检查重置、离开与重新进入，并确认关卡内没有模式切换入口，再将状态改为 `sample` 或 `ready`。

当前实现对桌面上移动的货块采用平面刚体求解（3D 仅负责显示），已支持推挤和双指接触摩擦；尚不包含离地抬升、侧翻、堆叠、轮胎打滑、真实电机电流与减速箱回差。停止按钮、失焦和离开关卡会暂停物理时间，恢复后继续；按键松开则在运行的物理世界中制动。

## 接触物理与实物校准

依赖锁定 `planck@1.4.2`，其测试台 peer 依赖 `stage-js` 通过根目录 overrides 锁定为 `1.0.1`，保持项目 Node 22 构建基线。运行页面不加载测试台。

参数集中在 `shared/src/third/physics.ts` 的 `THIRD_PHYSICS`，以下是可运行的演示值，并非实测结果：

| 参数 | 演示值 |
|---|---|
| 车体质量 | 1.2 kg |
| 货块质量 | 0.04 kg |
| 单夹指质量 | 0.02 kg |
| 地面滑动摩擦系数 | 0.25 |
| 夹指／货块接触摩擦系数 | 1.5 / 0.4（由引擎组合） |
| 驱动最大力 | 6 N |
| 转向最大力矩 | 0.25 N·m |
| 单指最大夹紧力 | 1.5 N |
| 单指开合速度 | 5 cm/s |

车体施加有限驱动力与转向力矩；夹指以带限位、有限力的滑动关节驱动，并采用对称联动约束，模拟同步平行夹爪；该约束仅连接左右夹指，不连接货块。实际夹爪若使用其他连杆结构，需按实物调整。地面阻力根据速度反向施加，且不会超过停止当前动量所需的力，避免静止物体被摩擦反向加速。自动程序按实际行驶距离／角度完成运动指令，开合指令会等待执行结果，末尾留出停稳时间。

实物校准建议：称量车体及货块；分别录制空载与推块前进 24 cm、90° 转弯、松键制动、夹爪空合、偏心夹块后的转弯。比较耗时、停止距离、货块偏移和滑脱阈值，再调整上述参数。若 DEMO 需要抬升或叠放，再增加完整的空间刚体与垂直夹爪自由度。

实现参考：[Planck 刚体世界](https://piqnt.com/planck.js/docs/world.html)、[滑动关节及有限力电机](https://piqnt.com/planck.js/docs/joint/prismatic-joint.html)。
