# 旷野淘金：2D 金币路径规划校园测试

这是一个可部署到单台服务器、供约 40 名学生同时使用的全栈项目。它包含同一套地图的 **20 个键盘任务（K01—K20）** 和 **20 个 Python 填空任务（P01—P20）**，关卡按无序收集、强制顺序、最小步数、障碍物、步数预算和多资源价值递进。

## 已实现

- 首次进入自动创建 UUID、随机玩家名，并记录学生的 Python/C++ 学习经历。
- 键盘方向键、WASD、屏幕方向按钮使用同一移动规则。
- 代码操控提供 `move_up()`、`move_down()`、`move_left()`、`move_right()` 四种指令条；点击加入编辑区，只在括号内填写 1—20 的移动步数，并可逐行删除。
- 障碍、边界碰撞、指定金币顺序、自动拾取、命令上限，以及“捡完即结束”或“预算耗尽即结算”规则。
- 客户端动画与服务端权威重放；最终成绩由服务端计算。
- 20 张地图、40 个任务、最多 8 个资源目标；第 19—20 关含价值 3 点的金币箱，教师最优步数与预算内最高价值不通过学生接口下发。
- 学生端桌面布局按 16:9 画布重构，5×5—9×9 地图可在标准 1280×720 视口内完整查看。
- 点击、按下、输入、聚焦、模式切换、选关、移动、拾取、开始、停止、运行和判分均带时间节点上报。
- 埋点断网时暂存在 `localStorage`，恢复后每 1.5 秒分批补传；SQLite 开启 WAL，适合课堂规模并发。
- 教师汇总接口和 attempts/events 的 CSV、JSONL 导出。
- DEMO 提取的车、金币、沙地和障碍贴图已用于界面。

## 统一赛事首页

访问 `/home/`（或 `/home`）可打开统一入口，按卡片进入旷野淘金、未来城市、生态农场、潮汐拾光和 DEMO 展示中心。首页复用赛事名称与主题素材，不需要填写身份信息。导航只从首页通向各入口，赛事与 DEMO 页面不新增相互跳转或返回统一首页的按钮。

原有地址保持不变：`/` 为旷野淘金，`/future/` 为未来城市，`/farm/` 为生态农场，`/beach/` 为潮汐拾光，`/demo/` 为 DEMO 展示中心。可收藏 `/home/` 作为日常访问入口。

## 四个主题模块的共用模板

旷野淘金、未来城市、生态农场和潮汐拾光以当前生态农场的精简界面为共用模板：完整欢迎页与身份预览、顶部操作方式和独立计时、左侧关卡及操作提示、右对齐的任务目标、中央大地图和右侧操作区。主题元数据集中在 `client/src/competition-modules.ts`；欢迎页、顶栏和任务条共用 `client/src/components/CompetitionTemplate.tsx`，主题保留各自配色、场景和关卡规则。

四个模块支持运行代码行高亮与自动滚动，停止后重置恢复场景并保留代码。旷野淘金和未来城市继续提供手动与编程两种模式，使用原服务端计分及独立正式次数；生态农场按关卡配置控制方式并保留本地采摘计分；潮汐拾光的前两关为手动驾驶，第三、四关为相同地图的编程竞速。赛事之间不提供跳转入口。

运行 `npm run test:template:browser` 验证前两个模块的共享模板、执行行高亮、部分执行后停止、重置保留代码、两种模式的正式成绩及四种屏幕布局。使用独立临时数据库，截图和报告输出到 `outputs/competition-template/`。

## 第三赛事：生态农场

`/farm/` 提供生态农场入口，姓名确认后选择三个草莓采摘关卡，沿用田野背景与绿色、麦黄色精简界面。左侧为 8×8 立体棋盘，右侧为程序编辑器；共用机器人运行时，在 `shared/src/farm/` 中隔离逐格采摘规则，DEMO 的 3D 物理玩法继续保留。

农场棋盘采用与未来城市相同的 Three.js + OrbitControls 技术，提供 3D、俯视、跟随、缩放、视角复位和含代码区的全屏模式。`StrawberryBoard3D.tsx` / `StrawberryScene.ts` 负责草莓、夹爪小车和坐标格的显示，逐格移动、障碍、采摘、交付与计分仍由原网格引擎决定。WebGL 不可用或丢失时自动显示原平面棋盘，草稿与当前任务状态保留。

三关均配置为编程控制，顶栏醒目提示，不提供模式切换。坐标从左下角 (0,0) 开始，横纵坐标 0–7；小车初始朝上。第一关草莓 (4,4)，第二关 (3,3)、(6,5)，第三关 (6,2)、(6,4)、(5,3)、(5,5)，配置见 `shared/src/farm/levels.ts`。任务地址为 `/farm/strawberry-1/` 至 `/farm/strawberry-3/`；旧 collect/place 链接分别归一到第一、二关。

六个操作入口为前进 `move(x)`、后退 `move(-x)`、左转 `turn_left()`、右转 `turn_right()`、采摘 `grab()`、放下 `release()`。移动参数为非零整数格数，转向固定 90°；不支持表达式或任意 Python 执行。小车停在草莓的上下左右邻居格且车头面向它后采摘，每次只能携带一株；草莓格采摘后可通行。小车到任意边缘格放下即交付，交付全部草莓才完成。越界、撞上草莓、无效采摘或放下会停止程序并说明原因；重新运行从初始状态开始。

运行时高亮当前代码行并自动滚动到该行。点击底部“停止”后，该按钮变为“重置”；重置恢复小车、草莓、计时与本轮步数，保留代码和个人最佳。编辑器右上角不再提供“重置代码”。

只有成功移动格数计入步数。使用 0–1 BFS 求精确最短路线，三关分别为 10、12、16 步；结束后展示最短步数。本地评分暂按 `floor(最短步数 / 本轮步数 * 100)`，最优路线 100 分，未完成 0 分。身份、草稿、完成进度和个人最佳步数独立保存于 `farm.*`；不提交其他赛事的成绩接口，不作为服务端正式成绩。草稿和最佳步数按关卡内容版本区分，历史 3D 任务记录不会混入。刷新深层地址后确认姓名即可返回任务。页面入口位于 `client/farm/index.html`。

运行 `npm test` 验证规则，`npm run test:farm:browser` 验证三关完整流程、评分保存、四种屏幕布局及原赛事回归；需要本机可用的 Playwright 与 Edge，可用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 路径。截图与报告输出到 `outputs/farm-strawberry/`，测试使用独立临时数据库。

## 第四赛事：潮汐拾光

`/beach/` 是海边拾贝主题入口，沿用生态农场的欢迎、身份、选关和任务布局，以海蓝、暖沙、珊瑚色和本地 SVG 海岸插画呈现。`/beach/shells-1/` 为「初潮寻贝」，两个贝壳的坐标固定为 `(36,70)`、`(18,80)`；`/beach/shells-2/` 为「四海拾珍」，四个贝壳为 `(30,32)`、`(84,38)`、`(36,78)`、`(88,90)`。地图 120×120 cm，左下角是坐标原点，X 向右、Y 向上；配置在 `shared/src/beach/levels.ts`，转换为世界坐标时使用 `z = 120 - Y`。

四关均为 3D 模拟。前两关固定为手动控制：W/S 或上下方向键前进后退，A/D 或左右方向键转向，G 合拢夹取，R 张开放下，也提供按住操作的屏幕按钮。`/beach/shells-3/`「初潮寻贝 · 编程」和 `/beach/shells-4/`「四海拾珍 · 编程」分别复刻前两关的贝壳坐标、小车起点与物理参数，固定使用代码操控。八种指令为前进 `forward(cm)`、后退 `backward(cm)`、移动到点 `move_to(X, Y)`、转到角度 `turn_to(deg)`、左转 `turn_left(deg)`、右转 `turn_right(deg)`、合拢 `grab()`、张开 `release()`。移动距离大于 0 且不超过 120 cm，左右转角度大于 0 且不超过 360°；移动到点使用 0–120 的整数厘米坐标定位车体中心，转到角度使用 0–360° 的绝对方向（0° 向上、90° 向右），精准定位的移动和转向速度为普通指令的 50%。每行一条指令，支持 `#` 注释，不开放循环、等待或按秒移动。运行时高亮并自动滚动到当前行，停止后重置保留代码。

贝壳沿用 6×6 cm 接触包围盒和已有夹爪物理，整个包围盒进入四周任一 12 cm 的浅蓝边缘带并停稳 0.4 秒即自动交付，不要求夹取或放下动作；直接推到位或仍在夹持时到位都有效。已交付贝壳保留在岸边并锁定；若仍在夹持，会自动张开夹爪，全部交付即完成。手动关版本为 `beach-1.1.0`，编程关为 `beach-code-1.0.0`，个人最快记录按关卡和版本隔离。

点击开始或运行程序即用单调时钟计时，慢帧不减免用时，不额外套用 DEMO 的 120 秒时限。得分为 `10000 / (100 + 用时秒数)`，保留两位小数，未完成得 0 分；同分比较原始用时。停止、失焦、切换标签页或 WebGL 中断都会结束本轮，重新开始会重置地图及计时。身份、个人最快用时与编程草稿保存在独立 `beach.*` 浏览器记录中，成绩和草稿按玩家、关卡、内容版本区分；与农场一致，当前为本地评分，未接入正式成绩后台。

`npm test` 包含四关完整物理交付、八种指令与坐标参数校验；`npm run test:beach:browser` 验证浏览器键盘完成第一关、程序完成第三和第四关、计时冻结、成绩和草稿保存、执行行跟随、第二关布局、深层路由和多种屏幕尺寸，使用独立临时数据库，截图与报告在 `outputs/beach/`。本机需有 Playwright 和 Edge，可用 `PLAYWRIGHT_MODULE` 指定依赖路径。完整物理路线测试程序保存在 `scripts/fixtures/beach-programs.json`。

## DEMO 展示中心

`/demo/` 提供玩法展厅与组件库：四个机器人 DEMO（八种体验组合）、一个交互计分 DEMO 和地图编辑器，支持主题、形式、操作方式、成熟度和组件筛选。每个 DEMO 有体验、规则、技术方案、版本与复用四个栏目，可下载配置。

地图编辑器体验地址为 `/demo/showcase/map-editor/experience/`，直接复用 `/editor/` 的组件和本机草稿，可绘制淘金与未来城市棋盘地图、检查试走并导入导出 `LevelDef` JSON。组件库提供接入说明；当前不编辑连续物理 3D 场地，也不会自动替换赛事地图。详见 [地图编辑器说明](docs/地图编辑器.md)。

通用目录在 `shared/src/gameplay/catalog.ts`，体验组件在 `client/src/demo/renderers.tsx` 注册。机器人控制提取到共享运行模块；计分 DEMO 与未来城市赛事共同调用固定的 `completion-efficiency@1.0.0`，保留原有服务端代码核验和计分结果。已发布规则有源码指纹校验，机器人与场景组件仍标为开发中。接入方式和边界见 [DEMO 开发说明](docs/第三子赛项_开发说明.md)。

旧 `/third/` 入口及其关卡深层地址已移除，访问返回 404。DEMO 不提交正式比赛成绩。

## 本地运行方式

需要 Node.js 22 或更高版本。服务端使用 Node 内置 SQLite，不需要额外数据库驱动。

```bash
npm ci
npm run build
npm start
```

浏览器打开 `http://localhost:3001/home/` 选择赛事。开发时可运行 `npm run dev`，统一首页为 `http://localhost:5173/home/`。

## 服务器部署

复制环境变量模板并设置真实域名和教师密钥：

```bash
cp .env.example .env
docker compose up -d --build
```

`data/` 必须放在持久化磁盘并定期备份。Nginx 示例位于 `deploy/nginx.coin-competition.conf`；把域名替换后启用，再配置 HTTPS。`PUBLIC_ORIGIN` 必须与学生实际访问地址完全一致，例如临时 HTTP 地址 `http://124.222.173.226:8106`，或正式 HTTPS 地址 `https://coin.example.com`。玩家 Cookie 会根据该地址的协议自动设置安全属性。

40 名学生无需分别启动进程。一个 Node 进程与一个 SQLite 数据库即可；客户端埋点已经合批，SQLite 使用 WAL、`busy_timeout=5000` 和 `synchronous=NORMAL`。若后续扩大到数百人或多台应用服务器，再迁移 PostgreSQL。

## 教师数据接口

浏览器访问 `/teacher` 可打开行为数据看板。看板包含课堂总览、模式比较、编程经历分组、关卡完成率、高频交互、每小时事件趋势和最近挑战记录，并支持下载成绩与原始埋点。

本地开发使用 `demo-teacher-key` 登录；生产环境使用 `.env` 中设置的 `TEACHER_KEY`。

如需直接调用接口，请在请求头中携带 `x-teacher-key: <TEACHER_KEY>`：

- `GET /api/teacher/dashboard`
- `GET /api/teacher/summary`
- `GET /api/teacher/export?kind=attempts&format=csv`
- `GET /api/teacher/export?kind=attempts&format=jsonl`
- `GET /api/teacher/export?kind=events&format=jsonl`
- `DELETE /api/teacher/data`（清空学生、挑战和埋点数据，不删除关卡配置）

开发环境未设置密钥时临时使用 `demo-teacher-key`；生产环境必须显式设置 `TEACHER_KEY`。

## 目录

- `client/`：React 学生端与全量交互埋点。
- `server/`：Express API、SQLite、权威回放、教师导出。
- `shared/`：客户端和服务端共用的规则引擎、BFS 求解器、受限 Python 校验器。
- `levels.teacher.json`：20 关教师内容包，含最优步数。
- `solutions.teacher.json`：教师参考路线，不由服务端公开接口提供。
- `docs/`：开发规范、关卡说明、埋点字典和 DEMO 复用说明。
- `scripts/`：关卡内容包生成、内容校验和 40 用户并发测试。

学生隐私数据和 SQLite 文件不会提交到 Git。正式采集前，请在学校许可范围内确定保存周期、访问权限和数据清理流程。
