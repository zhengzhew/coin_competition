# 旷野淘金：2D 金币路径规划校园测试

这是一个可部署到单台服务器、供约 40 名学生同时使用的全栈项目。它包含同一套地图的 **20 个键盘任务（K01—K20）** 和 **20 个 Python 填空任务（P01—P20）**，关卡按无序收集、强制顺序、最小步数、障碍物、步数预算和多资源价值递进。

## 已实现

- 首次进入自动创建 UUID、随机玩家名，并记录学生的 Python/C++ 学习经历。
- 键盘方向键、WASD、屏幕方向按钮使用同一移动规则。
- 代码操控提供 `move_up()`、`move_down()`、`move_left()`、`move_right()` 四种指令条；点击加入编辑区，只在括号内填写 1—20 的移动步数，并可逐行删除。
- 障碍、边界碰撞、指定金币顺序、自动拾取、命令上限，以及“捡完即结束”或“预算耗尽即结算”规则。
- 客户端动画与服务端权威重放；最终成绩由服务端计算。
- 20 张地图、40 个任务、最多 8 个资源目标；第 19—20 关含价值 3 点的金币箱，教师最优步数与预算内最高价值不通过学生接口下发。
- 学生端桌面布局按 16:9 画布重构，5×5—9×9 地图可在标准 1280×720 视口内完整查看。
- 点击、按下、输入、聚焦、模式切换、选关、移动、拾取、开始、停止、运行和判分均带时间节点上报。
- 埋点断网时暂存在 `localStorage`，恢复后每 1.5 秒分批补传；SQLite 开启 WAL，适合课堂规模并发。
- 教师汇总接口和 attempts/events 的 CSV、JSONL 导出。
- DEMO 提取的车、金币、沙地和障碍贴图已用于界面。

## 四个主题模块的共用模板

旷野淘金、未来城市、生态农场和潮汐拾光以当前生态农场的精简界面为共用模板：完整欢迎页与身份预览、顶部操作方式和独立计时、左侧关卡及操作提示、右对齐的任务目标、中央大地图和右侧操作区。主题元数据集中在 `client/src/competition-modules.ts`；欢迎页、顶栏和任务条共用 `client/src/components/CompetitionTemplate.tsx`，主题保留各自配色、场景和关卡规则。

四个模块支持运行代码行高亮与自动滚动，停止后重置恢复场景并保留代码，通关总分统一由后台教师 JSON 规则计算。旷野淘金和未来城市提供手动与编程两种模式，各模式正式次数独立；生态农场按关卡配置控制方式；潮汐拾光四关均为程序控制，第三、四关分别挑战单排 10 枚和 3 行 4 列共 12 枚贝壳。赛事之间不提供跳转入口。

运行 `npm run test:template:browser` 验证前两个模块的共享模板、执行行高亮、部分执行后停止、重置保留代码、两种模式的正式成绩及四种屏幕布局。使用独立临时数据库，截图和报告输出到 `outputs/competition-template/`。

## 第三赛事：生态农场

`/farm/` 提供生态农场入口，姓名确认后选择五个草莓采摘关卡，沿用田野背景与绿色、麦黄色精简界面。左侧为 8×8 立体棋盘，右侧为程序编辑器；共用机器人运行时，在 `shared/src/farm/` 中隔离逐格采摘规则，DEMO 的 3D 物理玩法继续保留。

农场棋盘采用与未来城市相同的 Three.js + OrbitControls 技术，提供 3D、俯视、跟随、缩放、视角复位和含代码区的全屏模式。`StrawberryBoard3D.tsx` / `StrawberryScene.ts` 负责草莓、夹爪小车和坐标格的显示，逐格移动、障碍、采摘、交付由网格引擎决定，总分由后台教师规则计算。WebGL 不可用或丢失时自动显示原平面棋盘，草稿与当前任务状态保留。

五关均配置为编程控制，顶栏醒目提示，不提供模式切换。坐标从左下角 (0,0) 开始，横纵坐标 0–7；小车初始朝上。第一关草莓 (4,4)，第二关 (3,3)、(6,5)，第三关 (6,2)、(6,4)、(5,3)、(5,5)；第四关“一排草莓”在 Y=4、X=0–7 放置 8 株；第五关“草莓方阵”在 X=3–5、Y=3–5 放置 9 株，形成左下角为 (3,3) 的 3×3 草莓堆。配置见 `shared/src/farm/levels.ts`。任务地址为 `/farm/strawberry-1/` 至 `/farm/strawberry-5/`；旧 collect/place 链接分别归一到第一、二关。

六个操作入口为前进 `move(x)`、后退 `move(-x)`、左转 `turn_left()`、右转 `turn_right()`、采摘 `grab()`、放下 `release()`。移动参数为非零整数格数，转向固定 90°；不支持表达式或任意 Python 执行。小车停在草莓的上下左右邻居格且车头面向它后采摘，每次只能携带一株；草莓格采摘后可通行。小车到任意边缘格、车头朝棋盘外放下即交付，交付全部草莓才完成。越界、撞上草莓、无效采摘或放下会停止程序并说明原因；重新运行从初始状态开始。

运行时高亮当前代码行并自动滚动到该行，暂停时冻结动画、高亮与计时。点击“停止”立即恢复小车、草莓、计时与本轮步数，保留代码和个人最佳。页脚统一展示交付进度、个人最佳、运行状态、步数、代码行数、用时及排行榜。

只有成功移动格数计入步数。0–1 BFS 求解器用于核验关卡路线，五关最短步数分别为 10、12、16、21、38 步，不参与总分计算。通关卡片和排行榜使用同一套教师 JSON 规则，由服务端综合步数、代码行数、用时生成总分；没有规则时显示“？？”。身份、草稿、完成进度和个人最佳步数独立保存于 `farm.*`，成功完成任务后每轮自动提交排行榜一次。草稿和最佳步数按关卡内容版本区分，历史 3D 任务记录不会混入。刷新深层地址后确认姓名即可返回任务。页面入口位于 `client/farm/index.html`。

运行 `npm test` 验证规则，`npm run test:farm:browser` 验证五关完整流程、评分保存、四种屏幕布局及原赛事回归；需要本机可用的 Playwright 与 Edge，可用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 路径。截图与报告输出到 `outputs/farm-strawberry/`，测试使用独立临时数据库。

## 第四赛事：潮汐拾光

`/beach/` 是海边拾贝主题入口，沿用生态农场的欢迎、身份、选关和任务布局，以海蓝、暖沙、珊瑚色和本地 SVG 海岸插画呈现。`/beach/shells-1/` 为「初潮寻贝」，两个贝壳的坐标固定为 `(36,70)`、`(18,80)`；`/beach/shells-2/` 为「四海拾珍」，四个贝壳为 `(30,32)`、`(84,38)`、`(36,78)`、`(88,90)`。地图 120×120 cm，左下角是坐标原点，X 向右、Y 向上；配置在 `shared/src/beach/levels.ts`，转换为世界坐标时使用 `z = 120 - Y`。

四关均为 3D 模拟，固定使用程序控制；已移除第一、第二关的手动版，并将原有两关编程版保留为第一、第二关。第三关 `/beach/shells-3/`「一排贝壳」为 10 枚贝壳单排等距排列；第四关 `/beach/shells-4/`「一堆贝壳」为地图中央的紧密 3 行 4 列方阵，共 12 枚，行列中心间距均为 14 cm，兼顾聚拢排列与夹爪操作空间。第四关从右侧通道出发，留出多次搬运和转向的空间。编程关显示贝壳初始坐标、地图刻度和小车坐标；手动界面隐藏这些坐标。

八种动作指令为前进 `forward(cm)`、后退 `backward(cm)`、移动到点 `move_to(X, Y)`、转到角度 `turn_to(deg)`、左转 `turn_left(deg)`、右转 `turn_right(deg)`、合拢 `grab()`、张开 `release()`。移动距离大于 0 且不超过 120 cm，左右转角度大于 0 且不超过 360°；移动到点使用 0–120 的整数厘米坐标定位车体中心，转到角度使用 0–360° 的绝对方向（0° 向上、90° 向右），精准定位的移动和转向速度为普通指令的 50%。支持 `for i in range(n):` 和 `for _ in range(n):` 循环，每层缩进 4 个空格，次数为 1–20，最多两层，展开后最多 256 条指令。每行一条指令，支持 `#` 注释，参数使用数字，不支持变量、表达式、等待或按秒移动。运行时高亮并自动滚动到当前行，停止后重置保留代码。

贝壳沿用 6×6 cm 接触包围盒和已有夹爪物理，整个包围盒进入四周任一 12 cm 的浅蓝边缘带并停稳 0.4 秒即自动交付，不要求夹取或放下动作；直接推到位或仍在夹持时到位都有效。已交付贝壳保留在岸边并锁定；若仍在夹持，会自动张开夹爪，全部交付即完成。前三关使用内容版本 `beach-code-2.0.0`，第四关紧密方阵使用 `beach-code-2.1.0`，个人最快记录与程序草稿按关卡和版本隔离，避免旧地图记录混入。

点击开始或运行程序即用单调时钟计时，慢帧不减免用时，不额外套用 DEMO 的 120 秒时限。物理运行使用固定 1/60 秒步长，累计帧间余量，避免小步长导致碰撞不稳定。编程模式可暂停和继续，暂停不计时；停止后重置地图及计时。身份、个人最快用时与编程草稿保存在独立 `beach.*` 浏览器记录中，按玩家、关卡、内容版本区分。全部交付后每轮提交排行榜一次；通关卡片和排行榜使用后台教师 JSON 规则计算的总分，未设置规则时显示“？？”，未完成不提交。

`npm test` 包含四关完整物理交付、循环语法与帧率回归、八种指令与坐标参数校验；`npm run test:beach:browser` 验证四关程序通关、新关卡循环交付、计时冻结、成绩和草稿保存、执行行跟随、关卡排列与坐标显示、深层路由和多种屏幕尺寸，使用独立临时数据库，截图与报告在 `outputs/beach/`。本机需有 Playwright 和 Edge，可用 `PLAYWRIGHT_MODULE` 指定依赖路径。完整物理路线测试程序保存在 `scripts/fixtures/beach-programs.json`。

`/demo/` 提供玩法展厅与组件库：四个机器人 DEMO（八种体验组合）、一个交互计分 DEMO 和地图编辑器，支持主题、形式、操作方式、成熟度和组件筛选。每个 DEMO 有体验、规则、技术方案、版本与复用四个栏目，可下载配置。

通用目录在 `shared/src/gameplay/catalog.ts`，体验组件在 `client/src/demo/renderers.tsx` 注册。机器人控制提取到共享运行模块，适用机器人 DEMO 的通关成绩与其他赛事统一使用后台教师规则。独立的计分演示仍用于解释固定的 `completion-efficiency@1.0.0` 示例；赛事保留旧算法供历史核验，不再将其作为学生总分展示。已发布示例规则有源码指纹校验，机器人与场景组件仍标为开发中。接入方式和边界见 [DEMO 开发说明](docs/第三子赛项_开发说明.md)。

旧 `/third/` 入口及其关卡深层地址已移除，访问返回 404。DEMO 不提交正式比赛成绩。

## 服务器部署

复制环境变量模板并设置真实域名和教师密钥：

```bash
cp .env.example .env
docker compose up -d --build
```

`data/` 必须放在持久化磁盘并定期备份。Nginx 示例位于 `deploy/nginx.coin-competition.conf`；把域名替换后启用，再配置 HTTPS。`PUBLIC_ORIGIN` 必须与学生实际访问地址完全一致，例如临时 HTTP 地址 `http://124.222.173.226:8106`，或正式 HTTPS 地址 `https://coin.example.com`。玩家 Cookie 会根据该地址的协议自动设置安全属性。

40 名学生无需分别启动进程。一个 Node 进程与一个 SQLite 数据库即可；客户端埋点已经合批，SQLite 使用 WAL、`busy_timeout=5000` 和 `synchronous=NORMAL`。若后续扩大到数百人或多台应用服务器，再迁移 PostgreSQL。

## 运行控制与排行榜

各编程入口支持在当前编辑位置插入指令，运行后显示“暂停 / 继续”和相邻的“停止”。运行及暂停时锁定代码；停止立即回到起点并保留代码。暂停期间不计时。金币、未来城市、草莓、海边和适用 DEMO 共用通关成绩组件及底部进度汇总，3D 地图共用位置状态栏和可展开操作说明。草莓交付需要小车停在边缘格且车头朝向棋盘外，新规则版本为 `strawberry-grid-2`。

游戏底部显示步数、代码行数、用时与排行榜。连续 3D 行驶按实际路程每 12 cm 折合 1 步；手动模式代码行数为 0。空行和注释不计代码行数，`#` 后的注释显示为灰绿色斜体。仅成功完成任务后提交排行榜，每轮一次；未完成、报错、主动停止均不提交。后台拒绝未完成记录，榜单也排除历史无效记录。

在 `/teacher` 的“全局排行榜设置”中指定开始／结束时间、编辑或导入 [JSON 示例](docs/leaderboard-rule.example.json)，再点击“保存排行榜设置”。设置保存到 SQLite，对金币、未来城市、农场、海边及 DEMO 的排行榜生效。各关卡、模式及新增场景的内容版本分别比较；每位玩家展示所选范围内最近一次成功完成的记录，“历史记录”显示时段之外的提交。未设置时间时展示所有时间内的成功记录。

总分由服务端计算：`base + steps × 步数 + code_lines × 代码行数 + seconds × 用时秒数`，限制在 `min` 至 `max`，保留两位小数。清空规则并保存后显示“？？”并禁止按总分排序。规则采用固定数字字段，不执行导入文件中的代码。修改规则会重新计算排行榜中已有记录的展示分数，通关卡片、个人最高分、排行榜、教师分析与导出均按当前规则展示；原始历史记录保留，通过后台只读计算统一分数。未完成记录不计分。

金币／未来城市复用既有后端提交；历史缺失代码或时间显示“—”，其综合分显示“？？”。新记录用时排除暂停，旧记录仍使用起止时间。农场由服务端回放代码核验步数，海边与 DEMO 的运动数据由本地模拟上报，用时也由客户端记录；该排行榜不提供防篡改的硬件比赛认证。此前仅存在浏览器中的农场／海边历史成绩不会自动补传。

验证：`npm test`、`npm run build`、`node scripts/verify-leaderboard.mjs`；安装 Playwright 或设置 `PLAYWRIGHT_MODULE` 后可运行 `node scripts/verify-controls-leaderboard-browser.mjs`，浏览器验收使用独立临时数据库。

## 目录

- `client/`：React 学生端与全量交互埋点。
- `server/`：Express API、SQLite、权威回放、教师导出。
- `shared/`：客户端和服务端共用的规则引擎、BFS 求解器、受限 Python 校验器。
- `levels.teacher.json`：20 关教师内容包，含最优步数。
- `solutions.teacher.json`：教师参考路线，不由服务端公开接口提供。
- `docs/`：开发规范、关卡说明、埋点字典和 DEMO 复用说明。
- `scripts/`：关卡内容包生成、内容校验和 40 用户并发测试。

学生隐私数据和 SQLite 文件不会提交到 Git。正式采集前，请在学校许可范围内确定保存周期、访问权限和数据清理流程。

修改范围约定：全局修改覆盖所有应用同一规则的比赛、关卡和模式；局部修改仅在用户明确标注的范围内生效。
